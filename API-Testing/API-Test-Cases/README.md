## 🔐 Авторизация

Для защищённых запросов используется токен авторизации.

Токен сохраняется в переменную окружения:

``` text
{{token}}
```

После успешного Login его можно автоматически записать из Response и
использовать в последующих запросах.

------------------------------------------------------------------------

## 🌐 Environment Variables

В коллекции используются переменные:

  Переменная       Назначение
  ---------------- -------------------------------
  `{{baseUrl}}`    Базовый URL API
  `{{email}}`      Email тестового пользователя
  `{{password}}`   Пароль тестового пользователя
  `{{token}}`      Токен авторизации
  `{{slug}}`       Идентификатор статьи

Чувствительные значения не публикуются в репозитории.

------------------------------------------------------------------------

## 🔄 CRUD

В тест-кейсах проверяется полный жизненный цикл статьи:

``` text
CREATE
   ↓
READ
   ↓
UPDATE
   ↓
DELETE
   ↓
GET deleted article → 404
```

Это позволяет проверить не только отдельные endpoints, но и связанный
пользовательский сценарий работы с ресурсом.

------------------------------------------------------------------------

## ❌ Негативные проверки

В набор включены проверки:

-   авторизации с неверными данными;
-   запроса без токена;
-   обращения к несуществующей статье;
-   получения удалённой статьи;
-   отправки некорректных данных.

Проверяется, что API корректно обрабатывает ошибки и не выполняет
недопустимые операции.

------------------------------------------------------------------------

## 📡 HTTP Status Codes

В практических сценариях проверяются:

  Status                       Значение
  ---------------------------- -------------------------
  `200 OK`                     Запрос успешно выполнен
  `201 Created`                Ресурс успешно создан
  `401 Unauthorized`           Требуется авторизация
  `404 Not Found`              Ресурс не найден
  `422 Unprocessable Entity`   Ошибка валидации данных

------------------------------------------------------------------------

## 🧪 Postman Tests

Для автоматической проверки Response используются Postman Tests.

Пример проверки HTTP Status:

``` javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});
```

Пример сохранения `slug`:

``` javascript
const jsonData = pm.response.json();

pm.environment.set(
    "slug",
    jsonData.article.slug
);
```

Это позволяет использовать данные одного запроса в последующих запросах
коллекции.
